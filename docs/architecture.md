# HDU Station：选课助手

## 范围

启动即进入选课对话。使用 Go、Wails 2、React 19、TypeScript、Eino、SQLite 和 YAML。没有远端 Station 后端，没有通用校园模式、Agent 选择、附件、任意 Shell 或 Sandbox。

桌面旧项目只用于理解接口与复用连接环境；本次重新实现聊天、模型适配、工具组合、存储和前端。保留当前仓库已有的带校验 QQ CLI 安装器。

## 调用链

```text
React → Wails App.Chat → Eino ReAct → DeepSeek V4.1 Flash
                              ↕
                    search_courses / read_course_posts / check_course_offerings / fit_courses_to_schedule
                              ↕
              QQ 频道 CLI / 赞哦 HTTP / 本机小红书 HTTP 服务 / Neo HTTPS
```

`App` 是唯一 composition root，装配配置、SQLite、模型与工具。最多同时运行10个不同对话，同一对话只允许一轮回答；每个请求有独立状态和取消上下文。用户可以在生成过程中切换历史，事件按请求与对话隔离。停止、超时和失败保留已显示的部分回答，重启时把未完成记录标记为中断。

QQ 默认启用并可关闭；赞哦和小红书是默认关闭的可选搜索来源，由 `App` 把配置快照传给统一的工具会话。前端仍只调用 Wails。小红书连接用户已经运行的本机 `xiaohongshu-mcp`，不增加远端 Station 后端，不从配置启动命令或进程。

## 模型与 Skill

`internal/agent/provider.go` 实现 Eino ToolCallingChatModel。模型接口使用 Chat Completions SSE，禁止带凭证重定向，不把上游错误原文返回界面。正式 DeepSeek API 使用 `deepseek-flash`；迁移网关使用其目录中的 `deepseek-v4.1-flash`。实测网关返回模型名 `deepseek-flash`。

内置六个短业务 Skill：`course-discovery` 负责社区发现/评价，`offering-verification` 负责开课，`timetable-fit` 负责本人课表与适配，`course-feasibility` 组合开课与课表。`course-collection-management` 管理课程收藏，`course-simulation-management` 管理 Neo 模拟课表。原 `course-favorites` 已删除。宿主将六份短说明装配到同一 Agent 提示中，模型按当前问题选择能力，不增加分类器或固定流程。仅问好课不自动读取校园，仅查课表可以直接结束。社区推荐允许 Agent 自由选择关键词与自然回答形式，不要求 JSON、固定表格、课程数量或反复闭包检索。三个频道 ID 只保存在 Skill 的作用域区，加载后注入宿主工具，不发送给模型。

模型引用本轮帖子编号时，宿主将它解析成已读原帖链接；赞哦没有可核实的网页链接，转换为小程序帖子编号和学校别名。流式分片使用同一转换。追问可以沿用历史完整回答中已验证的 QQ/小红书链接；本轮读过帖子却没有引用时，在回答末尾补充来源，不要求固定回答结构。小红书链接的签名仅由宿主在内存中暂存，点击时补上，不进入模型或 SQLite。

Eino 控制搜索与读帖循环。所有来源共同遵守每轮最多读取 12 个不同帖子的预算，社区与校园共用12次工具调用预算和最多六轮带工具模型请求限制总等待时间；之后保留一次无工具汇总。整轮最多六分钟，每个模型请求最多 90 秒，QQ CLI/赞哦请求最多 25 秒，小红书单次请求最多 75 秒，给上游 60 秒搜索期限和浏览器启动留出余量。小红书搜索、读帖遇到瞬时超时或服务端错误时最多重试一次，仍受整轮取消和期限约束；状态检查、认证失败、限流和格式错误不重试。预算是运行时限制，不是回答质量或格式门槛。

## 工具

- `search_courses`：默认用一个简短关键词覆盖所有已启用来源，也可指定 `source=qq/zanao/xiaohongshu`。返回来源、标题、日期、评论数及本轮帖子引用。QQ 每个频道最多 20 条；赞哦当前分类与一年内历史分类各取一页、各最多 20 条；小红书最多 20 条并补充杭电关键词。平台及频道失败不丢弃其余结果；未配置与确实无结果分别反馈。
- `read_course_posts`：一次读取最多六个已搜索到的引用，可混合不同平台。取得正文、原帖链接或小程序位置；QQ 最多两页评论及回复预览，赞哦和小红书只读取当前返回的评论与回复。截断、评论未读全和未读取的图片/音视频显式标记，重复引用复用本轮结果。

- `check_course_offerings`：1–12门候选课，按 `/academic/config` 的开课与课表默认学期确定查询范围；二者不一致时要求明确学期，不猜日期、不跨学期。依次按完整名称（最多两页，每页20条）和核心词（无精确同名时追加一页）调用 `/academic/class/search`，使用 `/academic/class/map` 解码校区与考核方式。模糊候选按课程号分组，保留不同教学班，由模型选择最接近的一个或多个原始 `courseIDs` 后继续核实。模型按用户问题决定是否选择课程号继续查，仅问有哪些可能课程时可直接展示未确认候选；候选的时间检查与名称匹配状态分开，不能把未选择误判为冲突。名称匹配保留推断性质，课程号保留前导零；分页覆盖未确认始终标 `partial`，空结果不等于未开课。
- `fit_courses_to_schedule`：补空默认 `scheduleSource=simulation`，固定读取同学期 `/academic/course-simulation` 的 `effectiveCourses`，使用结构化 slots 计算占用，模拟加入占位、模拟移除释放时间。每次适配重新读取当前版本，修改模拟方案会使已有适配结果失效；授权或数据不完整时不回退真实课表。仅明确查询真实课表时选 `scheduleSource=actual`，使用固定 `/academic/schedule` 请求同一学期，每页最多200条、最多10页，验证总数、偏移、下一页和重复页。仅解析白名单格式的 `classTime`，覆盖分段周次、单双周和多个上课时段，不用单个展开的 week/period 替代整门课程。缺页、错学期、格式未知时保留已知冲突，不确认空闲。`timeOfDay` 由 Go 确定性映射为上午1–5、下午6–9、晚上10–13节；多时段并集，与显式节次取交集，空交集报错而不放宽约束。Go 按全部周次、星期、节次及用户指定的星期/节次范围给出 fits、conflict、outside_preferences、already_enrolled 或 unknown；再按课程号分组，以有界回溯寻找门数最多、每课程号最多一个班且彼此无冲突的 suggestedPlan；最多12个课程号和100,000步，达到边界时公开标记尚未确认最多门数，保留可行方案，不执行加退课。

`show_course_results` 展示已取得的开课或本人课表结果，不要求所有请求都经过同一流程。只查本人课表时显示占用时段、学期与完整性；只查开课时可按星期、节次和时段过滤，不读取本人课表。课程时间与冲突状态由 Go 生成，公开表格及组合不展示班级号，内部仍用班级号定位。同一轮的社区经验摘要可以附在表格前；不额外附加模型对校园时间与冲突的自由转述。模糊候选可如实标为未匹配，不强制选一门才能回答。

搜索前，对所有启用来源并行执行一次连接检查，每个检查最多八秒。仅查询已连接来源；未登录、不可用的来源本轮跳过，不修改用户配置。搜索或读帖出错后，本轮不再反复请求该来源，其余来源继续提供结果。新一轮重新检查，恢复连接后可正常使用。

完成条件写在各业务 Skill 中：发现课程回答口碑和依据即可；开课核实给目标学期结果或缺口；单独课表查询给占用时段即可；用户要求“推荐并插空”时才要求候选、开课与本人课表适配的组合结果。运行时以实际查询响应判断是否展示校园结果，误调用展示工具不能覆盖纯社区回答；只要求已有校园结果用可靠展示器输出，不根据“读过课表”扩张任务、不强制下一工具为开课或展示。后续读取课表仍可复用同学期候选和本轮偏好。

校园查询每轮最多40次 HTTP 请求、最多三个并行开课请求，单请求25秒、响应最多2 MiB；开课工具150秒，课表筛选180秒，均受整轮取消约束。读取请求只使用固定 HTTPS GET 路由与当前账号授权头，禁止重定向与模型提供任意地址或学号。不读取成绩或学生名单。业务写例外仅限用户明确要求的课程收藏和 Neo 模拟方案管理，固定 POST `/academic/class/fav` 和 PUT `/academic/course-simulation`。局部修改保留未指定内容，整份替换/清空仅用于用户明确的对应要求。校园会话仅在本轮内复用学期、课程结果和完整课表；只向模型发送候选课程信息与必要的数值占用时段，模拟方案管理仅发送本人课程及教学班身份，其他查询仅发送必要占用时段；均不发送学生姓名、学号、令牌和原始响应。SQLite 只保存可见问答，不保存工具原始内容或课表缓存。

模型不能提供 guild ID、CLI 命令、Shell、登录令牌或任意 URL。CLI 参数和 HTTP 路由由宿主固定构造，没有解释器或动态 MCP 工具发现。输出只提取课程研究需要的文本、公开链接和小程序帖子位置；作者标识、联系方式字段、凭证、访问签名和游标不进入模型或 SQLite。QQ 共享客户端最多3个在途读取，全局每次发起至少间隔600ms；限流会触发全局70秒冷却并最多重试一次。排队、冷却和网络等待均可取消，取消不清除共享冷却。安装仅使用仓库已有的固定版本及完整性校验，不从 PATH 猜测二进制。

赞哦按上游协议构造学校请求头，只调用搜索、帖子详情、评论列表和设置中的登录状态检查。小红书 Agent 工具只调用 `/api/v1/login/status`、`/api/v1/feeds/search` 和 `/api/v1/feeds/detail`，服务地址限定为带端口的回环根地址，禁用代理与重定向。两个 HTTP 客户端都限制响应大小、保留取消上下文并屏蔽上游原始错误，同时区分超时、认证、限流、服务异常与无效响应。小红书诊断写入数据根目录 `logs/xiaohongshu-requests.jsonl`，仅含固定操作名、次数、耗时和结果类别，达到 1 MiB 时从头记录；不保存查询、URL、请求头或响应正文。发布、点赞、收藏、评论写入等业务写接口不注册给 Agent，也不暴露在 Wails。

默认学期可通过 `get_academic_term` 独立读取同一教务配置，不要求课程名、不读取课表；该工具和课程工具共享默认学期解析与结构化显示，未恢复强制推荐流程。

工具不解析用户问句，也不按问句改写时间参数或计算结果；星期、节次范围和时段交集由程序校验，歧义与矛盾由模型澄清。当前没有官方钟点到节次的对应能力，Skill说明这一边界，不提供钟点转换参数。

同一校园回答内按原查询名保留同学期候选；局部课程号选择不删除无关课程，明确 `replaceCandidates` 才收窄。时间条件改变时从结构化结果重算全部候选，不重放最后一个输入；未定名称候选可以展示已知时间核对，但不进入组合。原查询累计最多12个，跨轮不保存这些工具结果。

`show_course_results` 可按原始 `courseIDs` 局部选择本轮候选；仅名称选择复用已算的时间状态并重算组合，不重复读取课表，未完成或未知的时间证据不升级。省略 `courseIDs` 仍可展示未定候选。

课程检索结果仅保留已确认下沙校区的记录；其他校区不进入候选与排课。校区字典缺失或内部码无法解析时明确说明该部分未能核实，不输出内部码或把未知校区排为可用。

单独课表查询继续完整读取整学期；显示器按本轮指定的星期/节次收窄展示，合并同一节次的占用周次，明确区分已知占用与空闲。课表不完整时不确认空闲。

展示偏好的参数省略表示保留，显式空数组表示清空对应限制；只看课表与只查开课使用各自的展示偏好。已有课程适配在偏好更新后重新计算，不重复读取同轮已缓存的完整课表。

## 来源登录设置

QQ 和小红书使用同一个可展开来源卡片，折叠时只显示名称、登录状态和重新检查。展开后可即时保存启用开关、重新连接或清除登录凭证。小红书地址和服务访问 Token 继续保留在 YAML 中，但不再出现在普通设置页；保存模型或赞哦配置不会覆盖它们。

`source_settings.go` 提供固定来源枚举的 Wails 登录用例，与模型工具隔离。QQ 重新连接复用带完整性校验的安装器，通过固定 `login --yes --qrcode-path` 获取二维码，通过 `login poll-token` 领取并保存凭证；临时 PNG 位于数据根目录 `tools/qq-login/` 并在读取响应后删除。小红书通过 `DELETE /api/v1/login/cookies` 重置账号、`GET /api/v1/login/qrcode` 取码；其后台扫码过程保存 Cookie 后，Station 轮询状态确认连接。清除账号 Cookie 保留服务访问 Token。

前端只收到校验过的 PNG/JPEG data URL、会话 ID、过期时间和状态，不收到授权码或账号凭证。轮询串行执行，关闭设置、过期、切换登录会话时停止宿主轮询并忽略迟到响应；QQ 长轮询会取消并等待退出后再清除凭证。小红书上游的扫码浏览器由独立服务管理，在其二维码超时后关闭，关闭 Station 的等待界面本身不会撤销上游二维码。修改来源连接与正在进行的回答互斥，Agent 的来源列表和实际搜索都遵守启用开关。

小红书另有独立的「安全验证」设置动作，不清除登录 Cookie。连接组件识别搜索页面的安全验证跳转后，状态返回 `verification_required`，搜索立即停止并给出设置指引，不将其作为暂时故障重试。本机兼容补丁保留触发验证的浏览器和站点二维码最多 50 秒；设置用固定 security/qrcode、security/poll、security/cancel 接口管理等待。验证码过期、关闭设置或替换会话会停止等待；只有同一浏览器的真实搜索恢复且 Cookie 保存成功，才报告验证成功。旧版组件明确显示不支持。图片继续通过已有 PNG/JPEG 校验，远端会话 ID 只保存在宿主内存，不进入前端、模型、日志或 SQLite。

## 校园网页授权

设置中的「HDU CLI 登录」为开课查询与本人课表筛选提供授权。`campus_settings.go` 只向设置页暴露发起、查看状态、重新打开授权页、取消和退出用例。`internal/campusauth` 复用官方 CLI 的 RFC 8628 Device Authorization Grant：固定 `client_id=hduhelp-cli`，设备名为 `HDU Station`，申请 `academic:course:read`、`academic:schedule:read`、`academic:coursesimulation:read`、`academic:coursesimulation:write`、`academic:coursefavorite:read` 与 `academic:coursefavorite:write`，用户在网页明确批准后保存；既有课程授权不自动改写，保留课程查询，使用课表时提示重新授权，请求有效期 30 天，用户可在官方页面调整。直接调用固定 Neo HTTPS 接口，无需安装校园 CLI，也不使用共享 CLI 配置。

授权请求发至 `POST /open-apis/auth/device-authorization`，宿主仅允许打开 `https://neo.hduhelp.com/account/tokens/authorize` 并校验 `user_code` 与本次请求一致。后台按服务器间隔（至少五秒）调用 `POST /open-apis/authen/access-token`；处理 pending、slow_down、拒绝和过期，临时失败延长等待，始终受授权有效期约束。界面轮询只读内存，不触发额外上游请求。设备码与 PAT 不进入前端、模型、日志或 SQLite；前端只收到本次授权码、内部会话 ID、期限及状态。令牌响应必须确实包含且仅包含上述六项权限（顺序无关，拒绝重复、缺失或额外权限），不能把缺失 scope 当成已经批准。

关闭设置、取消、替换登录或退出应用会停止等待，并尝试取消远端设备请求；取消后迟到的令牌不会保存，若已领取则尝试自撤销。原授权在新的授权成功保存前继续保留；保存失败也会尝试撤销新令牌。登录状态只检查本机凭证是否存在及是否过期，不调用课程查询或其他业务接口验证连接。发起/退出与正在进行的回答互斥，等待网页授权时不能开始新回答。授权过期后引导重新授权，不使用原生会话的 refresh 接口。

校园账户数据原子保存至 `campus-auth.yaml`，保留稳定设备 ID、实际批准 scope、期限和 PAT。清除先提交本机空凭证，再通过 `DELETE /cli/tokens/current` 撤销当前 Station 授权；远端失败不会恢复本机凭证。重新授权只在成功保存新 PAT 后撤销 Station 管理的旧 PAT。历史 `campus_key` 仅在尚无新授权文件时兼容读取，不会被自动远端撤销；完成网页授权或本机退出后不会回退到旧令牌。

模拟选课权限只用于 Neo 模拟方案，不代表学校真实加退课权限。`manage_course_collection` 支持 read/rank/add/remove/update/replace/clear；读取列表后通过 `/academic/course?id=...` 批量补充公开课程信息，不解析学生名单字段。删除/换班需本轮读取过的收藏目标；新增班须本轮核实；clear/replace 需与本轮读到的完整列表一致。写入前读取最新列表，保留未指定内容，进程内串行修改、去重并复查。上游无 CAS，不能保证其他客户端同时覆盖时的原子性。

`manage_course_simulation` 支持 read/update/replace/reset；update 的 ENROLL/DROP 与 removeClassIDs 实现模拟加退课、换班、撤销动作。真实课程 ENROLL 视为撤销其模拟 DROP。写入前读取最新完整方案，校验本轮 revision 与调用参数，固定 expectedRevision 写入并读回复查；冲突或未知结果禁止本轮继续写入，不自动覆盖。新班必须同学期已核实；需要无冲突时，对修改后的全部真实/模拟课程逐周逐节检查，未知时间不放行。仅显示课程、教师、时间、真实/模拟状态，不向模型输出逐格 slots 或学生身份字段。

收藏和模拟方案分别授权、分别执行，不声称跨接口原子提交。管理结果由宿主渲染，模型回答中断时也保留已取得的回执。两类读写权限已包含在现有六项授权中，拥有完整授权无需再次登录；旧授权不自动补权，设置分别显示缺失权限。

## 终端显示

终端皮肤在 React 呈现层提供像素 HUD、逐字对话与情报表格，已移除录像带模式、噪点和特效转场。右上角按暖阳田园（`harvest`，浅色）、雾白青瓷（`porcelain`，浅色）、灰紫青绿（`violet`）、青蓝琥珀（`teal`）的顺序循环切换。页面、弹窗和首页杭电大门的 SVG 像素场景共用主题变量，原生控件跟随深浅色模式；新配置与未指定配色的旧配置默认暖阳田园，已有明确选择继续保留。桌面窗口底色与 HTML 首屏由宿主按已保存主题初始化，React 在设置连接检查完成前沿用此主题，避免默认浅色闪到已保存深色；仅向 HTML 注入白名单主题与底色。大门沿用用户照片中的圆孔高塔、玻璃楼梯间、桁架和门柱轮廓，改装为带分段光环、金属面板与导光轨道的赛博入口，后方保留部分高楼与天线；塔身中文校名已移除，材质和灯光随主题切换，随前端离线打包。窄窗口将欢迎语放在场景上方，完整保留高塔。浅色参考 [Solarized Light](https://ethanschoonover.com/solarized/) 的柔和底色与分层思路，采用暖灰、墨绿和青瓷色。暖阳田园参考 [《星露谷物语》官方场景](https://www.stardewvalley.net/)，采用奶油色纸面、木棕色边框、草绿与麦穗金，将相同校门轮廓置于原创像素山丘、木屋、风车和藤蔓花草中。模型内容和 SQLite 原文不因外观变化改变；取消、错误、历史读取及系统减少动态效果时直接显示已接收原文。`SaveAppearance` 在配置锁下只修改 `config.yaml` 的 `appearance.instant_text` 与 `appearance.theme`，允许在生成期间保存，不改写模型与来源设置，不使用 localStorage；保存失败保留原配色。实现与参考见 [终端设计记录](iterations/20260915-katana-zero-terminal.md)。

## 本机数据与迁移

新版使用独立应用数据根目录 `HDU Station Course`，避免覆盖旧版配置、数据库和技能。在 macOS 下为 `~/Library/Application Support/HDU Station Course`。开发或测试可显式设置 `HDU_STATION_DATA_ROOT`。

清理清单：`config.yaml`、`campus-auth.yaml`、`station.db` 及 WAL/SHM、`tools/`、`logs/`。`config.OwnedEntries` 记录同一清单。关闭应用后删除此目录即可移除全部新版持久数据。QQ CLI 继续复用自己的系统凭证存储（`qq-cli` / `token`）和 `~/.qqcli/.env` 回退，旧版 `.openclaw/.env` 回退中的 QQ 项也兼容；该登录不随应用数据根目录的清理删除。设置里的「清除登录凭证」会显式删除这项共享 QQ 登录及待授权状态，只移除对应 dotenv 变量，保留其他工具的变量和系统凭证。外部 mcporter 管理的凭证需要在原工具退出登录。

模型 Key、校园授权、赞哦 Token 与可选的小红书服务 Token 保存在权限为 0600 的 YAML。旧配置加载后默认关闭新的社区来源。设置页仅收到凭证是否存在、本机登录状态和授权流程状态。SQLite 只保存用户问题与可见回答；版本 3 移除旧课程分类缓存表及其索引，兼容版本 1 和 2 并保留对话记录，不新建课程缓存。未来数据库/配置/校园授权文件版本直接拒绝，不尝试降级覆盖。

小红书服务、账号 Cookie 和浏览器缓存由用户独立管理，Station 通过回环 HTTP 调用它；设置中的扫码、重连和清除账号操作也由该服务执行，不直接读写 Cookie 文件。来源配置步骤和已核对的上游版本见 [搜索来源配置](search-sources.md)。赞哦请求头适配的 MIT 许可随源码和构建产物附带。

`cmd/import-config` 是显式执行的一次性连接配置迁移工具，不在产品启动时读取 `.env`，也不自动扫描旧项目。模型凭证和 QQ 环境已按用户授权迁移，代码与凭证不会混入发布包。

## 验证

`make test`、`make frontend-check`、`make build` 检查单测、类型和桌面构建。`make e2e` 在桌面与 390px 窄窗口检查布局、对话、停止及设置；测试替身只存在于测试文件。

`make live-test` 显式使用本机真实配置，依次发送三个选课问题，要求实际 DeepSeek 模型、QQ 搜索、读帖、流式文本和可追溯原帖链接。脱敏可见回答写入数据根目录 `logs/acceptance.md`，用于人工核对内容。日常单测跳过这些联网调用。

问题集以用户删减后的53组、58轮为基准，按能力范围调整问法和预期。真实测试默认10路并发，每次写入独立的 `logs/skills-qa-*` 目录，保存题目快照、可见回答、脱敏工具名与范围越界标记；标记不代替逐题语义审核。
