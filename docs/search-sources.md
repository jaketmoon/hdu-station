# 选课搜索来源

在「助手设置」展开赞哦或小红书，填写连接信息并启用，点击「保存并检查」。默认搜索覆盖所有已启用的来源；也可以直接问“帮我只查小红书里的杭电通识选修体验”。未启用的新来源不会发出请求，已有 QQ 配置继续可用。

## 赞哦校园集市

1. 在电脑微信中登录自己的赞哦小程序。
2. 按 [ZanaoMCP 的获取 Token 说明](https://github.com/jeanhua/ZanaoMCP#获取-token)，从自己的小程序请求头获取 `X-Sc-Od`（Token）和 `X-Sc-Alias`（学校别名）。确认请求对应杭州电子科技大学，不要根据学校缩写猜别名。
3. 在助手设置中填写这两项，勾选「启用赞哦搜索」，保存并检查。

Station 直接调用同一组只读 HTTP 接口，无需另装赞哦 MCP 进程。每次关键词搜索读取当前分类和一年内历史分类各一页，去重后返回；读帖获取正文及当前返回的评论、回复预览。没有完整评论分页信息时会标记资料不完整。

上游接口没有提供可核实的网页分享地址，因此回答保留「赞哦帖子编号 + 学校别名」，供回到小程序按标题核对，不生成网页链接。连接失败时检查 Token 是否过期、学校别名是否正确，或稍后重试。

## 小红书

使用 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 的本机 HTTP 服务。Station 不负责安装或启动该服务。

1. 从上游 [Releases](https://github.com/xpzouying/xiaohongshu-mcp/releases) 下载与本机平台对应的主程序和登录工具，放在你管理的同一个目录中。
2. 在该目录中运行登录工具，按浏览器提示扫码登录，再运行主程序。首次启动可能需要等待上游准备浏览器。
3. 让服务保持运行，在 Station 中启用小红书，填写根地址 `http://127.0.0.1:18060`，不要填写 `/mcp` 或 `/api/v1`。
4. 如果服务使用 `AUTH_TOKEN` 开启了鉴权，把同一值填入「服务访问 Token」。这一项不是小红书账号 Cookie；未启用鉴权时留空。

例如 macOS Apple Silicon，在解压后的工具目录运行：

```sh
chmod +x ./xiaohongshu-login-darwin-arm64 ./xiaohongshu-mcp-darwin-arm64
./xiaohongshu-login-darwin-arm64
./xiaohongshu-mcp-darwin-arm64 -port 127.0.0.1:18060
```

登录工具和主程序需要使用同一份登录数据：默认在工作目录保存 `cookies.json`；若自行设置 `COOKIES_PATH`，两者应指向相同路径。账号、浏览器缓存和服务文件由这个独立工具管理，不属于 Station 创建的数据。

同一账号在另一个电脑网页端重新登录可能挤掉服务的登录状态。若普通浏览器打开原帖时提示「电脑设备登录超限」，可在手机小红书中查看；无需为了助手搜索而在普通浏览器再次登录。这是上游说明的网页端会话限制。

每次最多返回 20 个笔记，搜索会补充「杭电」关键词，仍需核对是否涉及其他学校。详情只读文字及当前评论，不加载全部评论、不识别图片或音视频。资料不完整时工具显式标记。

回答中的链接不含访问签名。当前应用进程会暂存已读笔记的签名，用于打开小红书原帖；重启后的历史链接可能需要重新查询，或在小红书中按标题搜索。

## 状态和凭证

- 「未启用」：该平台不会参与搜索。
- 「已连接」：本次登录状态检查成功；不保证平台之后每次请求都成功。
- 小红书「需要重新登录」：服务可连接，但账号未登录，请运行配套登录工具。
- 小红书「服务 Token 无效」：检查服务鉴权配置和 Station 中的访问 Token。
- 「暂时无法连接」：检查本机服务、端口、网络或赞哦凭证，准备好后再次保存并检查。

新增 Token 与模型 Key 一样存入应用数据根目录内权限为 `0600` 的 `config.yaml`。界面只收到“已保存”标记；留空保留现有凭证，勾选清除可删除凭证。清除赞哦 Token 前先取消启用，或同时提供替换值。

Agent 只注册 `search_courses` 和 `read_course_posts`。发布、点赞、收藏、关注、评论写入、私信、读取账号通知等接口均未接入。搜索结果中的作者标识、联系方式、账号 Cookie、服务 Token 和小红书访问签名不会作为字段传给模型或保存在 SQLite。

接口核对版本：赞哦 [`6b91407`](https://github.com/jeanhua/ZanaoMCP/tree/6b91407d84faa4a4b0746ad56925e544f6bdde69)，小红书 [`aad2a3d`](https://github.com/xpzouying/xiaohongshu-mcp/tree/aad2a3d249a347859975ce3b76d3442c4a027780)，2026-09-11。兼容性测试使用这些接口的脱敏结构；真实平台联调需要用户完成上述配置。

2026-09-11 在 macOS Apple Silicon 上使用小红书 [`v2.5.0`](https://github.com/xpzouying/xiaohongshu-mcp/tree/6583124dfda92312b6bc19a042a6acfae63fe498) 完成真实联调：扫码登录、搜索返回 20 篇笔记、读取前三篇正文及共 22 条评论/回复；桌面助手另完成一轮仅使用小红书的问答，生成 3 个原帖引用。赞哦暂缓联调，保持关闭。

后续用“高数”复现了超时：账号仍已登录、搜索状态已有 22 条结果，但整页稳定等待耗尽约 60 秒；当时统一错误提示误将它归入登录/连接问题。已通过 [本机兼容补丁](../scripts/patches/README.md) 改为等待搜索数据完成，修复后约 6 秒返回 20 篇笔记，并成功读取前三篇正文与评论。Station 同时区分超时、认证、服务故障等错误，对只读请求的瞬时超时或服务端错误最多重试一次；每次请求的固定类别和耗时保存在 `logs/xiaohongshu-requests.jsonl`，不记录原始工具内容或凭证。

本机联调所用服务、Cookie、浏览器及启动脚本统一放在应用数据根目录的 `tools/xiaohongshu-mcp/`，启动辅助程序在 `tools/source-setup`，随 `tools/` 一并清理。上游源码的本机补丁还增加 `XHS_BROWSER_CACHE_DIR` 绝对路径配置，将浏览器缓存放回该目录；这属于本机联调安装，不是 Station 产品的自动安装或进程管理功能。重启电脑后可运行该目录内的「启动小红书服务.command」，Cookie 有效时无需再次扫码。
