# 小红书搜索安全验证（侧对话修复）

## 原因与范围

登录接口返回已登录，但实际搜索跳转 `/website-login/captcha`，页面要求用已登录账号的小红书 App 扫码验证。普通设置重连清除 Cookie 后获取的是登录二维码，不能替代这个搜索验证。原等待耗尽约 60 秒，Station 又重试一次，并归类为未连接/暂不可用。

仅修改来源错误分类、设置登录用例与来源卡片、本机 v2.5.0 连接组件兼容补丁。保留本次开始前 main 上所有未提交的 Skill 拆分、并发和问题集改动；没有修改 Skill 和问题集。

## 实现

- 搜索识别安全验证页面后立即返回 HTTP 428；不重试，其他来源继续。
- 状态增加 verification_required，设置提供独立「安全验证」，保留原有 Cookie。
- 服务保留触发验证的浏览器会话，返回站点原生二维码；最多 50 秒，过期可重新获取。
- 设置轮询独立验证状态；只有验证后真实搜索成功并保存 Cookie 才显示恢复。
- 关闭、过期、替换会话不允许迟到结果授权；旧服务明确提示更新。
- 二维码和私有会话句柄仅在内存中，不进入模型、日志或数据库。
- 本机旧服务二进制备份为 tools/xiaohongshu-mcp/v2.5.0/xiaohongshu-mcp-before-security；已部署更新并重新打开桌面应用。
